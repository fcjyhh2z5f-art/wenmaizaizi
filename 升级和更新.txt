文脉在兹 · 升级与更新指南
========================================
适用：电脑版（Windows）、安卓版、iOS 离线版、网页版 PWA
版本基线：v3.0.0        整理日期：2026-11-11


一句话先记住
----------------------------------------
加书不用重装；换程序才要重装；iPhone 每 7 天要重签（这不算升级）；
任何升级之前，先在 App 里导出一次书库快照。

本软件刻意做成「零网络」：不会自动检查更新、不会后台偷偷升级、不会
上传你的书。所以升级永远是你主动做的一次动作，或者把新版文件包交给
我帮你替换。


一、先分清你遇到的是哪一种
----------------------------------------
| 情况 | 要不要重新装程序 | 怎么做 |
| 1. 导入新书、改检索词、增补简繁对照表 | 完全不用 | 直接在「导入」页 / 书库页操作，数据立即生效 |
| 2. 软件出新版（改了功能、界面、修了 bug） | 要，按端替换 | 见第三～六节 |
| 3. iPhone 用了几天 App 打不开了 | 不用重装、不用重新编译 | 签名过期：数据线连上，爱思助手点一次「重签」，书库还在 |
| 4. 网页版内容更新 | 不用重装 | 打开链接刷新一两次，详见第六节 |

第 1 种最常见。书库是数据、程序是壳，两者分开存，所以加书永远不需要
动程序；反过来，换程序也不该动书库（前提是别删数据目录、别改包名）。


二、升级前必做（三端通用）
----------------------------------------
在旧版里导出一份 JSON 快照，存到「文件」App / 电脑 / 网盘：
  · 电脑版：书库页 →「导出手机书库快照」
  · 手机端：书库 →「导出快照」
这不是形式主义：iOS 重签名、安卓换签名、网页清缓存这三种情况下，
唯一能救回书库的就是这份 JSON。导出只要几秒钟。


三、电脑版（Windows）怎么升级
----------------------------------------
数据位置：程序文件夹里的 data/
  data/catalog.json   书目与锚点索引
  data/books/         切分后的正文
  data/variants.json  你自己增补的简繁异体对照
  data/settings.json  设置
  inbox/              待导入的书

升级步骤：
  1. 关掉程序；
  2. 把旧文件夹里的 data/ 和 inbox/ 单独复制出来备份；
  3. 用新版整个文件夹覆盖（或只换 文脉在兹.exe 与 _internal/）；
  4. 把备份的 data/、inbox/ 放回原位；
  5. 重新打开，书库原样出现。

整个文件夹拷到别的电脑也能用，数据跟着文件夹走，路径无关。
想自己重新打包 exe：装好 PySide6 / pypdf 后双击 打包.bat；
版本号在 engine.py 的 VERSION = "3.0.0"。


四、安卓版怎么升级
----------------------------------------
  1. 把新的 文脉在兹.apk 传到手机；
  2. 直接点开覆盖安装（不用先卸载），书库数据保留；
  3. 若提示「应用未安装 / 与现有应用冲突」→ 说明两次 APK 签名不同
     （换了电脑编译、或 debug.keystore 变了）。此时：
       先导出快照 → 卸载旧版 → 装新版 → 导入快照。

本机重新编译：
  python prepare_apk_build.py     （第一次准备 JDK / SDK / Gradle，之后不用）
  python build_apk.py             （产出本目录 文脉在兹.apk）
也可以把工程推到 GitHub，用 .github/workflows/build-android.yml 云编译。
改了 iOS 版 web/ 之后，跑 python sync_web.py 会把改动同步到安卓端。
版本号在 android/app/build.gradle 的 versionCode / versionName，
升级发版时把 versionCode 加 1 更规范。
App 没有 INTERNET 权限，永远不会自动更新。


五、iOS 版怎么升级（步骤最多，但都是点几下）
----------------------------------------
A. 只是加书 / 换书库内容：不用动 App。电脑导出快照 → 传进手机 →
   App「导入」页选中即可。

B. 软件功能升级（拿到新版文件包后）：
  1. 把新版文件覆盖到你的 iOS 工程目录（默认 D:/download/文脉在兹_iOS离线版/）。
     注意保留隐藏的 .git/ 和 .github/，不要删、也不要重新建仓库；
  2. 双击 一键推送到GitHub.bat，直接回车（仓库地址已内置）。
     这一步既能首次安装，也能重复用于升级；改任何文件都会触发新构建；
     如果没改文件只想重编，去仓库 Actions 页点 Run workflow；
  3. 等 3～8 分钟，双击 一键取回IPA.bat。脚本会打印
     「附件更新时间 / 构建 SHA」，据此确认拿到的确实是新包；
  4. 爱思助手用【同一个 Apple ID】给新 IPA 签名，覆盖安装到手机。
     Bundle ID 不变、签名账号不变，书库一般保留；
  5. 万一装不上或数据没带过来：导出快照 → 卸载 → 装新版 → 导入快照。

C. 7 天签名到期（最常见、最容易误会成"要升级"）：
   不需要下载新 IPA、不需要重新编译、不需要导出快照之外任何操作。
   数据线连上电脑，爱思助手重新签名并安装一次即可，书库不丢。
   不想每周重签：改用自购 P12 证书 + 描述文件签名，有效期 1 年。

D. 升级时不要动的三样东西：
   · capacitor.config.json 里的 appId（cn.wenmaizaizi.app）——改了等于
     另一个 App，旧数据不继承；
   · web/ 里的文件名——必须纯英文，否则爱思助手报错误码 45；
   · .github/workflows/build-ios.yml 里的 Release TAG（v3.0.0）——
     取回脚本按这个 tag 找包。

E. 版本与缓存标记：
   · web/sw.js 的 CACHE 常量（网页版升级时改名字才会刷新离线缓存）；
   · workflow 每次构建用 --clobber 覆盖同一个 Release 附件，
     fetch_ipa.py 带 no-cache 请求并打印构建 SHA，避免下到旧包；
   · 想取回某个历史构建：python fetch_ipa.py --tag v3.0.0-build7。

网页版 PWA（保底方案）详见下一节；它不需要签名，也没有 7 天限制。


六、网页版 PWA 怎么更新
----------------------------------------
线上地址：https://wenmaizaizi-offline.app.workbuddy.host/?sharecode=TXQ5WI6RIB
（带 sharecode 的整条链接要一起保留，裸域名访问会被 403 拦住）

  · 我重新发布新版后，用手机打开这条链接，刷新 1～2 次；
    Service Worker 装好新版会自动清掉旧缓存；必要时完全关掉页面再打开。
  · 书库存在浏览器 / 主屏 WebView 的 IndexedDB 里，升级不会清空；
    仍建议按第二节先导出快照。
  · 发布版 sw.js 的 CACHE = wenmaizaizi-offline-v4；每次改资源要把
    版本号往上加（v5、v6…），否则手机可能一直用旧缓存。
  · 「添加到主屏幕」的图标不用重新添加，除非换了图标或改了 manifest。


七、三端书库保持一致的最省事节奏
----------------------------------------
把电脑当主库：新书都在电脑导入（8 类格式全支持）→ 导出快照 →
传进两台手机。手机上随手新增 / 标注 → 导出快照 → 在电脑点
「导入手机书库快照」回灌。合并按书的 id 覆盖，不会清空其它书，
往返后锚点编号不变。

升级程序不改变快照格式；新旧版本都能读 wenmaizaizi-snapshot，
也继续兼容早期的 myhistorylib-snapshot。


八、怎么知道有新版
----------------------------------------
因为零网络设计，程序不会自己提示更新。看这三处即可：
  · 我交给你的新版文件包 / 新版 APK / 新 zip；
  · GitHub 仓库 Release v3.0.0 的附件更新时间与构建 SHA；
  · 各端版本号（engine.py VERSION、build.gradle versionCode、
    sw.js CACHE）。


九、四个最常见的坑
----------------------------------------
  1. 删了 data/ 或把新版装到另一个 appId → 书库"消失"，其实只是换了位置；
  2. iOS 用不同 Apple ID 重签覆盖 → 可能被判为不同签名，先导出快照再装；
  3. 网页版只刷新一次就判断"没更新" → Service Worker 通常要两次；
  4. 把唯一一份书库押在 7 天签名上 → 定期导出快照存到「文件」App。

一句话收尾：书是数据，App 是壳。备份快照，然后放心换壳。
